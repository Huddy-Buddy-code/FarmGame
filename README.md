# Farm Logistics Sim

A browser-based farm-and-ranch **logistics & economy** simulator played over real
USDA satellite imagery of a real US county. See [`PROJECT_BRIEF.md`](./PROJECT_BRIEF.md)
for the full vision, scope, and architecture contracts — it is the single source of truth.

**Counties (2026-07-26):** any CONUS county. The home screen (shown every
launch) lists your farms and lets a new farm pick any state + county. Story
County, Iowa ships bundled (instant); any other county is built at first play —
roads fetched live from the Overpass API (~10–30 s), then cached in IndexedDB.

## Run it

```bash
npm install
npm run dev      # http://localhost:5173
```

Other scripts: `npm run typecheck`, `npm test`, `npm run build`.

## Where things are

| Path | What |
|------|------|
| `public/counties/<id>/` | **A playable "map" package** — `manifest.json` (identity, UTM zone, bounds, imagery) + `roads.geojson` (bundled OSM extract). Add a county = add a folder. |
| `public/counties/index.json` | **The national county index** — every CONUS county (id, FIPS, name, state, bbox, center), generated by `tools/build-county-index.mjs`. |
| `src/county/types.ts` | County package types (`CountyManifest`, `CountyPackage`). |
| `src/county/registry.ts` | `loadCounty(id)` resolution: bundled folder → IndexedDB cache → live Overpass build. |
| `src/county/countyIndex.ts` | Loads the index; derives UTM zone from longitude. |
| `src/county/overpass.ts` | Overpass query + conversion — the road-extract recipe (`EXTRACT_RECIPE_VERSION`; bump it when the recipe changes to invalidate caches). |
| `src/county/builder.ts` | Synthesizes a manifest + fetches roads (mirrored, with progress) for non-bundled counties. |
| `src/county/idbCache.ts` | Best-effort IndexedDB cache of runtime-built counties. |
| `src/ui/homeScreen.ts` | The main menu: farm list + state/county picker with NAIP thumbnails. |
| `src/config/gameConfig.ts` | **Pillar 1** — the single config object (balance numbers only). |
| `src/geo/coords.ts` | **Coordinate system** — one internal UTM-meter space; `setProjection()` per county. |
| `src/sim/clock.ts` | **Pillar 2** — the sim clock (pause, time-compression, queued future actions). |
| `src/state/saveState.ts` | **Pillar 4** — the save-state shape. |
| `src/map/naip.ts` | NAIP satellite base layer, built from a county's imagery manifest. |
| `src/map/roadsLayer.ts` | Renders the county's bundled road extract as vector lines. |
| `src/map/routing.ts` | Real-road routing (OSRM). |
| `src/main.ts` | Entry point: loads the county package, then builds the map from it. |

## Bundling a county (optional — any county already works via the picker)

Bundle a county when it should load instantly/offline (like story-ia):

1. Create `public/counties/<id>/manifest.json` (copy story-ia's; set name, FIPS,
   UTM zone, bbox, center, imagery ImageServer). `<id>` must match the county's
   id in `public/counties/index.json`.
2. Drop in `roads.geojson` — an OSM extract of the county's roads, each feature
   tagged `{ major: 0|1, hw }` (same recipe as `src/county/overpass.ts`).
3. Add `{ id, name }` to `BUNDLED_COUNTIES` in `src/county/registry.ts`.

No engine or UI code changes — counties are pure data.

## Regenerating the county index

1. Download and unzip (outside the repo):
   <https://www2.census.gov/geo/tiger/GENZ2024/shp/cb_2024_us_county_500k.zip>
2. `node tools/build-county-index.mjs <dir-with-the-.shp>`
3. Review the `public/counties/index.json` diff; `npm test` validates it
   (count, id/FIPS uniqueness, CONUS envelope, spot-checked UTM zones).
